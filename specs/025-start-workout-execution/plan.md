# Implementation Plan: Start Workout Execution

**Branch**: `025-start-workout-execution` | **Date**: 2026-05-31 | **Spec**: [spec.md](spec.md)
**Input**: Adapt Start Workout flow — new `POST /api/work-executions/start` response shape; update active workout screen data model.

## Summary

The existing `POST /api/work-executions/start` integration uses a legacy response shape (`StartSessionResponse` with `SessionExercise`/`SessionSet`). The server now returns `workExecutionId`, `workoutPlanName`, `totalNumberOfSets`, and `exerciseBlockPlans[]` with `targetSets[]`. All response DTOs, the domain models (`WorkoutExercise`, `WorkoutSet`, `SetProgress`), and the `ActiveSessionViewModel` must be updated. The active session UI removes the `muscle` subtitle and PR badge (not in new API) and replaces the "PREVIOUS" column with `targetWeight`. `workExecutionId` is retained in `ActiveSessionViewModel` for future use.

## Implementation Notes

### New DTOs in `WorkoutExecutionModels.swift`

```swift
struct StartWorkoutResponse: Decodable, Hashable {
    let workExecutionId: Int
    let workoutPlanId: Int
    let workoutPlanName: String
    let totalNumberOfSets: Int
    let exerciseBlockPlans: [ExerciseBlockPlan]
}

struct ExerciseBlockPlan: Decodable, Hashable {
    let exerciseBlockPlanId: Int
    let exerciseId: Int
    let exerciseName: String
    let orderIndex: Int
    let restSeconds: Int
    let isOptional: Bool
    let numberOfSets: Int
    let targetSets: [TargetSet]
}

struct TargetSet: Decodable, Hashable {
    let targetSetId: Int
    let orderIndex: Int
    let targetReps: Int
    let targetWeight: Double
}
```

### Updated `toWorkoutSession()` mapping

```swift
extension StartWorkoutResponse {
    func toWorkoutSession() -> WorkoutSession {
        WorkoutSession(
            id: workExecutionId,
            name: workoutPlanName,
            exercises: exerciseBlockPlans
                .sorted { $0.orderIndex < $1.orderIndex }
                .map { block in
                    WorkoutExercise(
                        exerciseBlockPlanId: block.exerciseBlockPlanId,
                        id: block.exerciseId,
                        name: block.exerciseName,
                        restSeconds: block.restSeconds,
                        sets: block.targetSets
                            .sorted { $0.orderIndex < $1.orderIndex }
                            .map { WorkoutSet(targetReps: $0.targetReps, targetWeight: $0.targetWeight) }
                    )
                }
        )
    }
}
```

### `CheckInView` navigationDestination update

```swift
// Before:
.navigationDestination(for: StartSessionResponse.self) { response in
    ActiveSessionView(
        viewModel: ActiveSessionViewModel(
            workout: response.toWorkoutSession(),
            mood: response.feeling
        ),
        onComplete: { dismiss() }
    )
}
.onChange(of: viewModel.sessionResponse) { _, response in
    if let r = response { path.append(r) }
}

// After:
.navigationDestination(for: StartWorkoutResponse.self) { response in
    ActiveSessionView(
        viewModel: ActiveSessionViewModel(
            workExecutionId: response.workExecutionId,
            workout: response.toWorkoutSession(),
            mood: mood?.rawValue.uppercased() ?? ""
        ),
        onComplete: { dismiss() }
    )
}
.onChange(of: viewModel.sessionResponse) { _, response in
    if let r = response { path.append(r) }
}
```

Note: `viewModel.sessionResponse` type changes from `StartSessionResponse?` to `StartWorkoutResponse?`.
