# Implementation Plan: Edit Existing Workout Plan

**Branch**: `017-edit-workout-plan` | **Date**: 2026-05-17 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/017-edit-workout-plan/spec.md`

## Summary

Users with an active workout plan can edit it via a new "My Plan" menu item. Tapping it opens the existing multi-step wizard pre-filled with the full plan data fetched from `GET /api/workout-plans/current`. All fields are editable. On wizard completion, a single `PUT /api/workout-plans/{id}` updates the existing plan server-side, preserving the plan's ID. The menu item is enabled only when `TodayViewModel.hasActivePlan` is `true`.

## Technical Context

**Language/Version**: Swift 5.10 / iOS 17+  
**Primary Dependencies**: SwiftUI (`@Observable`), URLSession via existing `NetworkClient`; no new SPM packages  
**Storage**: No new local persistence; edit data is in-memory during the wizard session  
**Testing**: XCTest (`@MainActor` unit tests following existing patterns)  
**Target Platform**: iOS 17+ Simulator + device  
**Project Type**: Mobile app (iOS)  
**Performance Goals**: Plan pre-fill completes in < 3 s on a standard mobile connection; wizard Continue response < 300 ms (local state only in edit mode)  
**Constraints**: Bearer token injected by `NetworkClient`; no PII in logs; grayscale UI only  
**Scale/Scope**: 1 active plan per user; ~8 modified files; ~2 new model structs
